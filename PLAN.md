# Orbis Control — план

Единственный план проекта. Других планов, логов планирования и evidence-файлов в
репозитории нет и не заводится. Правила работы — [`AGENTS.md`](AGENTS.md);
поведенческие сценарии — [`docs/acceptance.md`](docs/acceptance.md).

Цель: приложение для ASUS-ноутбуков под Linux с функционалом уровня G-Helper /
g-helper-linux, без root-GUI, с честными состояниями (поддержка определяется по
runtime-evidence, запрос ≠ применено, неизвестный исход не повторяется).
Референс поведения — `~/g-helper-linux` (только изучение, код не копируется: GPL).
Целевая машина разработки — TUF A17 FA707NV (Ryzen 7 7940HS + RTX 4060), Arch/CachyOS.

## Что уже работает (fake/P2P-тесты, без свежей живой проверки)

- Профили Тихий/Сбалансированный/Турбо (через power-profiles-daemon, read-back).
- Кривые вентиляторов CPU/GPU по профилям, сброс на заводские с read-back.
- Лимиты SPL/SPPT/FPPT, NVIDIA Dynamic Boost, целевая температура GPU
  (Hardware1 + polkit + read-back; Apply открывается по typed probe).
- Лимит заряда батареи.
- Режимы GPU Eco/Standard/Ultimate с очередью и «нужна перезагрузка».
- Panel Overdrive, яркость подсветки клавиатуры, Aura Static RGB.
- Телеметрия/дашборд, диагностика с экспортом, трей, автозапуск, настройки.
- Только чтение: мощность NVIDIA,
  лимиты CPU из Armoury.
- Пакет: `packaging/arch/PKGBUILD`, hardwared/sessiond, D-Bus, polkit.

Решение по UI: контрол показывается только если у него есть рабочий владелец и
capability подтверждена на машине. Неподдерживаемые — скрыты или честно
недоступны; инертных заглушек нет.

## Этап 4. Паритет с G-Helper (после v0.1)

Порядок — по пользе для FA707NV. Каждая функция: provider с capability-evidence →
typed владелец (Hardware1 для привилегированного, user-компонент для остального) →
UI → read-back → тесты на fake/P2P.

### 4.0 Найдено на FA707NV (приоритет)
- [x] Лимиты мощности через `asus-nb-wmi` (`ppt_pl1_spl`, `ppt_pl2_sppt`, `ppt_fppt`,
      `nv_dynamic_boost`, `nv_temp_target`): `asus-armoury` на этом ядре отдаёт ENODEV
      (в его DMI-таблице нет FA707). Диапазоны — из явной таблицы проверенных моделей
      по токену DMI (`FA707NV`: 15–90 Вт, boost 5–25 Вт, temp 75–87 °C); чтение и
      запись Hardware1 (polkit `set-power-limit`, `ReadWritePaths` в юните), read-back —
      кэш драйвера, который обновляется только после подтверждения прошивкой. Модели
      вне таблицы остаются без записи. Проверено на fake-путях; вживую не проверено
      (исходное значение прошивки не читается — драйвер отдаёт 5, откат невозможен
      до смены профиля).
- [x] Эффекты Aura на TUF: asusd заявляет только Static, поэтому hardwared пишет
      фиксированный кадр в `kbd_rgb_mode` (Static/Breathe/Rainbow Cycle/Rainbow Wave/Pulse).
      Атрибут только для записи: результат — «отправлено, не подтверждено» (outcome 1), UI
      показывает эффект из памяти, пока конфиг asusd не изменился. Вживую на FA707NV
      Breathe и Pulse отправлены без ошибки, Static 0,246,255 возвращён; визуально глазами
      не подтверждено.
- [x] Слайдеры (лимит заряда, лимиты мощности) управляются клавиатурой: стрелки, PageUp/Down,
      Home/End, применение по паузе 0,6 с или Enter; на ручке виден фокус.

### 4.1 Профили как в G-Helper
- [x] Лимиты мощности (SPL/SPPT/FPPT), Dynamic Boost, temp target хранятся для
      каждого профиля (`profile-limits.toml`, только явно применённые значения) и
      повторно применяются при смене профиля, если включено «Запоминать для этого
      профиля» (внешняя смена — Fn+F5/PPD — ловится опросом). Первое наблюдение
      профиля при запуске ничего не пишет. Проверено тестом воркера с приватным
      D-Bus-пиром; вживую не проверено.
- [x] EPP (amd-pstate) и CPU boost: запись через Hardware1 (`set_cpu_epp`/`set_cpu_boost`,
      polkit `set-cpu-tuning`, read-back по всем CPU), карточка «Процессор» в Performance,
      значения хранятся на профиль вместе с лимитами и повторно применяются при смене
      профиля. Проверено тестами на подменённом sysfs и воркера с фейковым бэкендом;
      вживую не проверено (нужна установка пакета и разрешение на запись).
- [x] Кривые вентиляторов применяются вместе с профилем: их хранит и применяет asusd, а не
      Orbis. Вживую на FA707NV (2026-09-29): при смене профиля через PPD в
      `asus_custom_fan_curve` подставляется сохранённая кривая профиля (включённая —
      `pwm_enable=1`, выключенная — авто `2`), возврат в `balanced` возвращает его кривую.
      Запись своей кривой в неактивный профиль через Orbis вживую не проверялась.

### 4.2 Автоматика по питанию
- [x] Профиль при AC / батарее: правила «от сети» / «от батареи» (`power-rules.toml`,
      выключены по умолчанию), движок в воркере срабатывает только по смене
      источника питания (первое наблюдение при запуске ничего не пишет; смена во
      время сна ловится первым замером после пробуждения), пишет через тот же
      авторизованный путь профиля и затем повторно применяет лимиты профиля.
      Старая gated-off подсистема automation (~8k строк) удалена. Проверено
      тестами воркера. Вживую проверено на FA707NV (2026-09-29, пакет 0.1.0-7): включение
      ничего не пишет; правка правила текущего источника применяет его один раз,
      неактивного — не трогает профиль; реальное отключение/подключение зарядки
      переключает профиль (`balanced` ↔ `quiet`) за ~0,5 с; правила переживают рестарт GUI.
      Повтор лимитов профиля вживую не проверялся.
- [x] GPU Optimized (как в Windows G-Helper): карточка «Optimized» на странице «Графика»; выбор хранится
      в `power-rules.toml` (`gpu_optimized`, не зависит от главного переключателя правил). При смене
      источника питания и при первом наблюдении после запуска воркер читает статус пары ASUS и через тот же
      авторизованный `SetProductGpuMode` ставит в очередь Standard (сеть) или Eco (батарея); совпадающая
      цель и нечитаемый статус ничего не пишут, автоматическое переключение не выводит из Ultimate,
      ошибка/неизвестный исход не повторяются. Ручной выбор Eco/Standard/Ultimate выключает Optimized.
      Проверено тестами воркера с фейковым источником; вживую не проверено (нужно разрешение на
      постановку режима в очередь).
- [x] Частота экрана: ручное переключение и правило «Гц» для AC/батареи на странице «Экран».
      Только KDE: `kscreen-doctor -j` для чтения и `output.<имя>.mode.<id>` для записи
      (фиксированные аргументы без shell, успех только после read-back); без KDE — честно
      недоступно. Вживую на FA707NV (2026-09-29, dev-сборка): 144 ↔ 60 Гц из GUI подтверждается
      `kscreen-doctor`; правка Гц правила текущего источника применяется один раз, правило
      неактивного источника панель не трогает. Реальное отключение зарядки с правилом Гц вживую
      не проверялось (профильная часть правил так проверена).
- [x] Таймаут подсветки клавиатуры: карточка «Автоотключение подсветки» (Никогда/15 с/30 с/1 мин/5 мин
      отдельно для сети и батареи, `keyboard-timeout.toml`). Простой определяется по Wayland
      `ext-idle-notify-v1`, яркость меняется через logind `Session.SetBrightness` (не Hardware1, не
      прямой sysfs), успех — по чтению уровня; выбранный пользователем уровень не перезаписывается,
      восстановление при вводе, смене настроек/источника и выходе (в т.ч. SIGTERM). Только Wayland-сессия,
      работает пока запущен GUI; без композитора карточка честно показывает недоступность. Вживую на FA707NV
      (2026-09-29, KDE Wayland, dev-сборка): 15 с → яркость 2→0, ввод возвращает 2, цикл повторяется,
      выход GUI возвращает уровень. Совместное действие с PowerDevil не исследовалось.
Движок правил — в user-компоненте, вызывает те же авторизованные пути Hardware1.

### 4.3 GPU tuning
- [x] NVIDIA: смещения core/memory (NVML в hardwared, read-back; спящую GPU не будим). Значения
      хранятся по профилям и повторно применяются при смене профиля (fake-тест). Живая проверка
      FA707NV (2026-09-29): смещение ядра 0 → +50 (через D-Bus) → -50 (слайдер GUI) → 0, read-back
      совпал; память (+1800 у драйвера) не трогали. Для записи unit-файлу нужен CAP_SYS_ADMIN.
      Лимит мощности скрыт: драйвер не отдаёт текущее значение (read-back невозможен).
      Повтор при смене профиля вживую не проверялся.

### 4.4 CPU tuning
- [x] AMD STAPM/fast/slow: на FA707NV это те же SPL/SPPT/FPPT из `asus-armoury` (раздел «Лимиты
      мощности»); отдельная запись через ryzenadj конфликтовала бы с прошивкой ASUS и не добавлена.
- [ ] AMD Curve Optimizer (все ядра, −30…0) через `ryzenadj --set-coall`: реализовано в коде
      (typed `SetCurveOptimizer` в Hardware1 + polkit `set-curve-optimizer`, фиксированный запуск
      `/usr/bin/ryzenadj` без shell, карточка «Процессор», хранение по профилям, подтверждение для
      значений ниже −15, «Сбросить в 0»; скрыто без ryzenadj/ryzen_smu). Fake-тесты зелёные.
      Вживую на FA707NV прошивка отклоняет `--set-coall/--set-coper/--set-cogfx` («rejected by SMU»):
      демон отвечает NotSupported и переводит статус в Unsupported, GUI показывает честную ошибку и
      скрывает блок. Успешная запись проверяется только на машине, где SMU принимает CO (чтения у
      ryzenadj нет, успех = ответ SMU); до этого пункт остаётся открытым.

### 4.5 Подсветка и ввод
- [x] Эффекты Aura (Breathe, Pulse, Rainbow, …) по возможностям устройства (см. 4.0).
- [x] FnLock и переназначение Fn-клавиш: на FA707NV не поддерживаются. Ядро (`asus-wmi`, 7.2.8) не
      создаёт sysfs-атрибута FnLock (есть только `fnlock_default` при загрузке модуля и внутреннее
      состояние по Fn+Esc), asusd такой интерфейс не отдаёт, так что нет ни чтения, ни записи, ни
      read-back. Переназначение клавиш потребовало бы общего input-ремаппера (hwdb/keyd) вне границ
      Hardware1. Контрол не добавляется; вернуться при появлении устройства с атрибутом.

### 4.6 Дисплей и звук
- [x] Яркость экрана: слайдер на странице «Экран». Чтение — sysfs `/sys/class/backlight` (firmware >
      platform > raw), запись — logind `Session.SetBrightness` (не Hardware1, не прямой sysfs), успех
      подтверждается чтением, минимум 1 % (экран не гасится); внешние изменения подхватываются
      опросом раз в 3 с. Вживую на FA707NV (2026-09-29, с разрешения, dev-сборка, KDE): 60 % → 50 %
      (120 → 100 в sysfs) → 60 % (120), исходное значение возвращено.
- [ ] Гамма/цветовая температура: у KWin нет переносимого API (только Night Light), отложено.

### 4.7 Прочее
- [x] Статистика в трее: подсказка значка (SNI `ToolTip`) показывает температуры и обороты CPU/GPU и
      заряд батареи с источником питания из свежей телеметрии GUI; неизвестные значения не выводятся,
      устаревшие помечены. Вживую на FA707NV (2026-09-29, dev-сборка, KDE): свойство `ToolTip` на
      session bus содержит актуальные значения; сам всплывающий текст глазами не смотрел. Мощность
      в подсказку не входит (источника телеметрии мощности на этой машине нет).
- [x] Проверка обновлений: в «О программе» кнопка «Проверить обновления» (только по нажатию) читает
      последний релиз GitHub через `curl` с фиксированными аргументами (`--proto =https`, таймаут,
      лимит размера; `curl` добавлен в depends пакета) и сообщает «последняя версия» / «доступна X,
      обновите через pacman» / ошибку. Ничего не скачивает и не ставит. Вживую (2026-09-29, dev-сборка,
      KDE Xwayland): нажатие дало «Установлена последняя версия (0.1.0)».

Не для этой машины (делать только при появлении устройства): AnimeMatrix/Slash,
ROG Ally, XG Mobile, MiniLED, NumberPad, мыши ASUS.
