# ADR 0001: Rust + Slint

- Статус: **Принято** (Этап 0/1, 2026-08-06)
- Дата: 2026-08-06

## Контекст

Нужен нативный Linux GUI для системного приложения с плотным G-Helper-подобным
интерфейсом, поддержкой Wayland (основная) и X11 (совместимость), без Electron/
WebView/Node/Python, с низким потреблением памяти и быстрым стартом. Основной
язык — Rust (по заданию). Требуется декларативный UI, тестируемость (screenshot-
тесты), единый набор иконок, дизайн-токены.

## Рассматривавшиеся варианты

1. **Slint** — декларативный, Rust-first, своя дизайн-система, Wayland+X11 через
   winit/femtovg/skia, `slint-viewer` для превью и скриншот-тестов, fractional
   scaling, лицензия Royalty-free (GPLv3-совместимый вариант доступен).
2. **GTK4 + gtk4-rs** — зрелый, но layout-модель и темизация далеки от плотного
   кастомного G-Helper-стиля; большой системный dependency surface.
3. **iced** — чисто Rust, но экосистема/стабильность API на момент решения менее
   подходит для сложных кастомных контролов и точного pixel-контроля.
4. **Avalonia (utajum/g-helper-linux)** — C#/.NET; требует runtime, не подходит под
   «чистый Rust, лёгкий» и репозиторий без лицензии (риск).
5. **Tauri/WebView** — запрещено заданием (Electron/WebView/Node).

## Решение

Использовать **Rust stable (edition 2024)** + **Slint** для GUI.

Обоснование:

- Соответствует требованиям задания (Rust, Slint, декларативная дизайн-система).
- Slint позволяет точно воспроизвести плотный G-Helper-лейаут (свободная
  компоновка, фиксированные размеры в logical px).
- Есть официальные инструменты для visual regression (рендер в CI).
- Backend для Wayland и X11 из коробки; без WebView.
- Возможность держать GUI в отдельном crate без аппаратного I/O.

## Последствия

- Положительные: единый язык, сильная типобезопасность, `cargo`-инструментарий,
  малый размер бинарника, лёгкие тесты.
- Отрицательные: Slint-специфичные знания; необходимость поддерживать MSRV
  (закрепляется в `rust-toolchain.toml`); некоторые сложные контролы (график
  кривой) — собственная реализация в Slint (собственный компонент `FanCurveChart`).
- Риски: версии Slint меняются — закрепить версию в `Cargo.toml` workspace;
  проверка актуальных API через context7 на Этапе 2.
- Решение не затрагивает бэкенд: провайдеры/демон полностью независимы от GUI.
